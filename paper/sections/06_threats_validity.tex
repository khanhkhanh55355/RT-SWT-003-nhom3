\section{Threats to Validity}
\label{sec:threats-validity}

We follow the usual internal, external, construct, and conclusion validity structure used in software engineering experiments~\cite{arcuri2011practical}. The intent here is simple: state what could distort the results and how we limited that distortion.

\textbf{Internal validity.}
Reproducibility is harder with commercial LLM endpoints because the system behind the same API call can change over time. Even small updates in routing or decoding may shift generations from one run to the next. We kept the setup stable by pinning the model version (\texttt{gpt-4o-2024-11-20}) and using deterministic decoding (\texttt{temperature}$=0$, \texttt{top\_p}$=1.0$). We recorded the full request trace (timestamp, returned model name, token usage, and cost) in \texttt{results/full\_api\_log.txt}. Temporary failures were retried with exponential backoff so that missing outputs would not bias the sample.

\textbf{External validity.}
The data come from a single industrial context: IntelligenceBank product backlogs. This narrows generalizability to other organizations and to teams that write user stories differently. We mitigated this only to the extent the corpus allows: we sampled across four product domains and relied on the public dataset of Rathnayake et al.~\cite{rathnayake2026llm}, so the same materials can be used for replication.

\textbf{Construct validity.}
Semantic similarity based on embeddings is an indirect proxy. It reflects overlap in meaning with the expert reference, but it does not tell us whether a scenario is ``good Gherkin'' in the practitioner sense (e.g., independently testable steps or appropriate scenario focus). To avoid over-interpreting similarity, we added executable syntax rate and checked executability with the official Gherkin parser~\cite{cucumber2023gherkin}. In other words, our evaluation requires both semantic proximity and syntactic validity.

\textbf{Conclusion validity.}
The study uses $N=100$ pairs. This is adequate for a single full-sample hypothesis test, but it is underpowered for detailed domain-by-domain comparisons, where moderate differences may be missed. Thresholds and test directions were set during a pilot phase ($N=20$) and then kept fixed. We did not run a formal a priori power analysis for the full-sample Wilcoxon test in RQ1; we treat that as a limitation. To make the results easier to interpret, we report effect sizes together with exact $p$-values (Cliff's $\delta$ for RQ1; Cohen's $h$ for RQ2).
