\section{Research Method}
\label{sec:method}

\subsection{Dataset}
\label{sec:method-dataset}

We built our evaluation sample from the industrial corpus released by Rathnayake, Shahin, and Abaei (2026) at RMIT University~\cite{rathnayake2026llm}, publicly available at \url{https://github.com/amilarathnayake1/LLM-BDDGeneration}.
The original dataset comprises 500 paired user stories and manually authored Gherkin scenarios drawn from four IntelligenceBank software products, organized into four domains: Digital Asset Management (150 pairs), Brand Management (125), Marketing Operations Platform (150), and Marketing Compliance (75)~\cite{rathnayake2026llm}.

Following Rathnayake et al., we retained only pairs that satisfy two quality filters: Connextra-style user stories (``As a \ldots, I want \ldots, So that \ldots'') and Gherkin scenarios containing explicit Given/When/Then structure.
This filtering yielded 348 valid pairs suitable for automated evaluation.

From the filtered pool, we drew a stratified random sample proportional to domain representation, using random seed~42, resulting in a working dataset of $N{=}100$ pairs stored as \texttt{data/sampled\_100.csv}.
Expert reference scenarios are provided in the \texttt{Manual Scenario} column; Rathnayake et al.\ report that these were written by QA developers and validated by six BDD experts with more than ten years of experience~\cite{rathnayake2026llm}.
In our experiments, \texttt{Manual Scenario} serves as the ground-truth Gherkin against which generated outputs are compared.

\subsection{Experimental Setup}
\label{sec:experimental-setup}

Khánh executed the generation experiment by calling the GPT-4o API once for each of the 100 sampled user stories.
We used the pinned model version \texttt{gpt-4o-2024-11-20} with temperature set to~0, $top\_p{=}1.0$, and a maximum completion length of 512 tokens.
The generation strategy was zero-shot: no examples were supplied to the model at inference time.

Our prompt was adapted from Figure~2 of Rathnayake et al.~\cite{rathnayake2026llm}:
\begin{lstlisting}
You are a QA expert. Generate a BDD scenario for this User Story.
User Story: <user_story>
Use the following format:
Scenario: [Scenario name]
Given [precondition]
When [action]
Then [expected result]
Make sure to: 1. Use clear and specific steps. 2. Include all necessary preconditions.
3. Describe the main action clearly. 4. Specify concrete expected results.
5. Use business language. 6. Do not include explanations or multiple scenarios.
7. Focus on the most important happy path scenario.
\end{lstlisting}

The execution pipeline loaded \texttt{data/sampled\_100.csv}, submitted each user story to the GPT-4o API, stripped non-Gherkin text from the returned response, and saved the generated scenarios to \texttt{results/full\_llm\_output.csv}.
An empty response was recorded in \texttt{results/full\_api\_log.txt} and retried once rather than being silently discarded.

Our replication package, including datasets, prompts, scripts, and raw results, is publicly available at: \url{https://github.com/khanhkhanh55355/RT-SWT-003-nhom3}.
