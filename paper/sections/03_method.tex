\section{Research Method}
\label{sec:method}

\subsection{Dataset}
\label{sec:method-dataset}

We built our evaluation sample from the industrial corpus released by Rathnayake, Shahin, and Abaei (2026) at RMIT University~\cite{rathnayake2026llm}, publicly available at \url{https://github.com/amilarathnayake1/LLM-BDDGeneration}.
The original dataset comprises 500 paired user stories and manually authored Gherkin scenarios drawn from four IntelligenceBank software products, organized into four domains: Digital Asset Management (150 pairs), Brand Management (125), Marketing Operations Platform (150), and Marketing Compliance (75)~\cite{rathnayake2026llm}.

Following Rathnayake et al., we retained only pairs that satisfy two quality filters: Connextra-style user stories (``As a \ldots, I want \ldots, So that \ldots'') and Gherkin scenarios containing explicit Given/When/Then structure.
This filtering yielded 348 valid pairs suitable for automated evaluation.

From the filtered pool, we drew a stratified random sample proportional to domain representation, using random seed~42, resulting in a working dataset of $N{=}100$ pairs stored as \texttt{data/sampled\_100.csv}.
Expert reference scenarios are provided in the \texttt{Manual Scenario} column; Rathnayake et al.\ report that these were written by QA developers and validated by six BDD experts with more than ten years of experience~\cite{rathnayake2026llm}.
In our experiments, \texttt{Manual Scenario} serves as the ground-truth Gherkin against which generated outputs are compared.

\subsection{Experimental Setup}
\label{sec:experimental-setup}

Khánh executed the generation experiment by calling the GPT-4o API once for each of the 100 sampled user stories.
We used the pinned model version \texttt{gpt-4o-2024-11-20} with temperature set to~0, $top\_p{=}1.0$, and a maximum completion length of 512 tokens.
The generation strategy was zero-shot: no examples were supplied to the model at inference time.

Our prompt was adapted from Figure~2 of Rathnayake et al.~\cite{rathnayake2026llm}:
\begin{lstlisting}
You are a QA expert. Generate a BDD scenario for this User Story.
User Story: <user_story>
Use the following format:
Scenario: [Scenario name]
Given [precondition]
When [action]
Then [expected result]
Make sure to: 1. Use clear and specific steps. 2. Include all necessary preconditions.
3. Describe the main action clearly. 4. Specify concrete expected results.
5. Use business language. 6. Do not include explanations or multiple scenarios.
7. Focus on the most important happy path scenario.
\end{lstlisting}

The execution pipeline loaded \texttt{data/sampled\_100.csv}, submitted each user story to the GPT-4o API, stripped non-Gherkin text from the returned response, and saved the generated scenarios to \texttt{results/full\_llm\_output.csv}.
An empty response was recorded in \texttt{results/full\_api\_log.txt} and retried once rather than being silently discarded.

Our replication package, including datasets, prompts, scripts, and raw results, is publicly available at: \url{https://github.com/khanhkhanh55355/RT-SWT-003-nhom3}.

\subsection{Evaluation Metrics}
\label{sec:metrics}

We evaluate the generated Gherkin scenarios along two independent dimensions: semantic alignment with expert-written scenarios, and syntactic executability.

\textbf{Metric 1: Cosine Semantic Similarity.}
Both the LLM-generated scenario and the corresponding QA-expert (ground-truth) scenario are embedded using OpenAI's \texttt{text-embedding-3-large} model~\cite{openai2024embeddings} via the OpenAI Embeddings API, producing vectors $v_{\text{llm}}$ and $v_{\text{gt}}$.
The similarity score for each pair is $\text{score} = \cos(v_{\text{llm}}, v_{\text{gt}})$, computed with scikit-learn's \texttt{cosine\_similarity}.
The pre-registered success threshold is $\geq 0.85$.
An earlier project draft considered \texttt{sentence-transformers} (\texttt{all-MiniLM-L6-v2}, Reimers and Gurevych~\cite{reimers2019sentence}) for this metric; this was superseded before the pilot phase in favor of OpenAI embeddings (\texttt{text-embedding-3-small} for the pilot, \texttt{text-embedding-3-large} for the full run), and \texttt{all-MiniLM-L6-v2} was not used to produce any reported result in Section~\ref{sec:results}.

\textbf{Metric 2: Executable Syntax Rate.}
Each generated scenario is parsed with the official Gherkin parser, \texttt{gherkin-official} v28.0.0~\cite{cucumber2023gherkin}, via its Python \texttt{gherkin.parser.Parser} class.
Because the parser requires a \texttt{Feature:} header, a synthetic \texttt{"Feature: Generated scenario"} header is prepended only when the raw LLM output does not already start with one; parsing is otherwise performed on the unmodified model output.
A scenario is scored PASS (1) if it parses without error and FAIL (0) otherwise.
The pre-registered success threshold is an executable rate $\geq 80\%$.

\subsection{Statistical Analysis}
\label{sec:stats}

Both thresholds (0.85 for cosine similarity, 0.80 for executable rate) and both test directions were fixed during the pilot phase ($N{=}20$) and were not altered after the full-scale data ($N{=}100$) were observed.

\textbf{RQ1 --- Cosine Semantic Similarity.}
We test $H_0: \text{median cosine similarity} \leq 0.85$ against $H_1: \text{median cosine similarity} > 0.85$ using a one-sample, one-tailed Wilcoxon signed-rank test (\texttt{alternative="greater"}, \texttt{zero\_method="wilcox"})~\cite{wilcoxon1945} applied to the signed differences $\text{score}_i - 0.85$ for $i = 1, \dots, 100$.
$H_0$ is rejected only if both the observed median $\geq 0.85$ \emph{and} $p < 0.05$.
Effect size is reported as Cliff's $\delta$, computed here in its one-sample / threshold-comparison form, $\delta = \frac{|\{i : \text{score}_i > 0.85\}| - |\{i : \text{score}_i < 0.85\}|}{n}$~\cite{arcuri2011practical}.

\textbf{RQ2 --- Executable Syntax Rate.}
We test $H_0: \text{executable rate} \leq 0.80$ against $H_1: \text{executable rate} > 0.80$ using a one-tailed exact binomial test (\texttt{scipy.stats.binomtest}, \texttt{alternative="greater"}, $p_0=0.80$)~\cite{arcuri2011practical}.
$H_0$ is rejected only if the observed rate $\geq 0.80$ \emph{and} $p < 0.05$.
Effect size is reported as Cohen's $h$, $h = 2\arcsin\sqrt{\hat{p}} - 2\arcsin\sqrt{0.80}$.
The 95\% confidence interval is the exact (Clopper--Pearson) one-sided interval consistent with the one-tailed test direction, as returned by \texttt{BinomTestResult.proportion\_ci(0.95, method="exact")}.

A post-hoc power analysis was not performed for either test on the full sample; this is noted as a limitation rather than assumed (see Section~\ref{sec:threats-validity}).
